# Workflow Guard Rails（工作流守护护栏）

面向多步骤 Agent 工作流的安全护栏层。它**包裹**而非替代你的工作流逻辑，用七项守卫拦截工作流自身看不到的失败。

## 为什么需要它

LLM 和 Agent 工作流的失败方式，传统错误处理会漏掉：

- 工具调用返回"成功"但输出无效 → **假成功**
- 副作用在验证前就触发 → 损坏内容到达用户
- 重试跑了两次 → **重复发送**
- 微小偏离跨运行累积 → **静默漂移**直至崩溃

Workflow Guardian 在这些边界上拦截。

## 七项守卫

| # | 守卫 | 拦截 |
|---|---|---|
| 1 | 执行前检查 | 前置缺失、范围错误 |
| 2 | 检查点 | 中途不可恢复崩溃 |
| 3 | 副作用队列 | 损坏内容到达用户 |
| 4 | 预算重试 | 重复发送、局部损坏 |
| 5 | 结果验证 | 假成功 |
| 6 | 审计记录 | 上下文丢失、漂移不可见 |
| 7 | 规则沉淀 | 反复出现却未固化的错误 |

## 工作方式

1. **执行前**：校验输入、权限、成功标准、幂等键（守卫 #1）
2. **执行中**：在每个不可逆边界发出检查点（守卫 #2）
3. **外部动作前**：入队，验证通过才释放（守卫 #3）
4. **产出后**：跑独立断言（守卫 #5），失败在预算内重生（守卫 #4）
5. **成功后**：写审计记录（守卫 #6），从确认失败中提议新规则（守卫 #7）

## 关键模式

- **结果验证**：不要相信"工具返回 OK"。强制自检 + 代码独立验证。断言 `A == B` 时也要断言 `A > 0`。
- **副作用队列**：外部动作只在验证通过后触发。
- **漂移监控**：跨运行追踪合规率，而非单期。首次偏离即预警。
- **规则沉淀**：确认的失败升级为常驻断言。

## 人工确认点

以下情况必须显式确认：首次高权限工具、任何不可逆/外部动作、低置信结果、重试预算耗尽、写入新守卫规则。

## 输出

```
🛡️ Guardian Report
- 执行前检查: ✅ / ❌
- 检查点: N
- 副作用入队: N, 已执行: N
- 验证: ✅ / ❌ (断言: X/Y 通过)
- 重试: N / 预算
- 审计记录: 已写 / 跳过
- 新规则提议: 是/否
- 结论: ✅ 放行 / ❌ 交人工
```

## 局限

- 守卫 #5/#6 只拦机器可检查的问题。风格、语义、判断漂移需要独立审核层。
- 每次运行增加一次验证步骤（<20% 开销）。
- 只保护经过队列的动作。
